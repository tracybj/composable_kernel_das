6/7组原方向权重预排核超过同轮最好raw控制；K512用例反而更慢，因此不能统一启用。预排核198VGPR，raw控制214VGPR；均64KB LDS、无scratch/spill。寄存器减少、物理请求布局改变同时存在，当前实验不能把收益精确拆成某一种原因的占比。内部转置后预排激活的额外结果保存在CSV/JSON，不能按静态权重摊销。

转换采用预分配输出的PyTorch permuted-view GPU copy，warmup2/repeat5、3样本中位数；不声称该转换本身已优化。表内转换成本不含输出分配、CPU描述符与调度；一次使用的GPU分项和只是转换/计算两项中位数相加，不是完整API端到端实测。摊销次数按`pack_ms + reuse*packed_gemm_ms < reuse*best_raw_gemm_ms`计算，假设权重在这些使用间完全不变，且不计分配等额外成本。M16384/N4096/K6144/G8约两次复用即可超过该raw控制，但预排后核仍低于冻结BLAS目标；不是已经达标。

结论：用户提供的FP8代码带来了可验证的新方向。值得继续优化B布局与数据供给，而非继续仅扫A寄存器批量或提前B预取。若允许模型加载时缓存预排权重，可维护显式packed-weight入口、失效规则、原始NT fallback和按M/N/K/G选择；若必须原始NT且每次准备都计时，需要继续研究高效转换或片上B重排/计算融合。两种接口的成绩分别验收。
